# AGENTS.md — Cudy TR3000 ImmortalWrt Firmware Project

This file is the canonical reference for AI coding agents working on this repository.  
It captures the project's architecture, key conventions, file semantics, and workflows so that agents
can reason about the codebase accurately and make safe, context-aware changes.

---

## 1. Project Overview

**Goal:** Build a lean, up-to-date ImmortalWrt 24.10 firmware image for the Cudy TR3000 v1 router
(MediaTek MT7981 / Filogic 820, Linux 6.6 kernel) with closed-source hardware acceleration, and
publish it as a GitHub Release.

The entire build runs in GitHub Actions. This repo is the _build recipe_ — it does not contain the
OpenWrt source tree, only the configuration, custom scripts, file overlays, and workflows that drive
the CI pipeline.

| Attribute            | Value                                                                   |
|----------------------|-------------------------------------------------------------------------|
| Target device        | Cudy TR3000 v1                                                          |
| Upstream source      | [padavanonly/immortalwrt-mt798x-24.10](https://github.com/padavanonly/immortalwrt-mt798x-24.10) |
| Upstream branch      | `openwrt-24.10-6.6`                                                     |
| Kernel               | Linux 6.6                                                               |
| Target triplet       | `mediatek/filogic`                                                      |
| Subtarget arch       | `aarch64_cortex-a53`                                                    |
| Hardware accel       | MTK closed-source MT Wi-Fi + wired acceleration                         |
| Output image prefix  | `{YYYYMMDD}-24.10-6.6-{device}-{version}-{hash}-rootfs`                |
| License              | MIT                                                                     |

### 2.1 Workflow Semantics

The CI uses a **two-tier orchestration pattern**:

1. **`openwrt-builder.yml`** — the orchestrator. It defines a `setup` job that reads env vars
   (source URL, branch, config file paths, etc.) and forwards them to `image-builder.yml` via
   workflow outputs. After the build completes, an `update-cache` job persists the upstream
   repo hash as a GitHub Actions cache key so `update-checker.yml` can detect changes.

2. **`image-builder.yml`** — the reusable build engine. It accepts all parameters via `workflow_call`
   inputs, runs the standard OpenWrt build sequence (clone → feeds update → feeds install →
   config override → `make download` → `make`), and publishes the firmware artifact either as a
   CI artifact (`upload_firmware`) and/or a GitHub Release (`upload_release`). It outputs the
   upstream source commit hash (`repo_hash`) for cache-key chaining.

3. **`update-checker.yml`** — runs on a cron schedule (`0 0 */5 * *`, every 5 days) or via
   `workflow_dispatch`. It queries the upstream repo's API (`padavanonly/immortalwrt-mt798x-24.10`,
   branch `openwrt-24.10-6.6`) for the latest commit hash. If the hash differs from the cached
   value, it triggers the main build workflow. It also monitors the upstream `defconfig` path
   (`defconfig/mt7981-ax3000.config`) and creates an issue when a new defconfig is detected.

4. **`clean-up.yml`** — invoked at the end of `update-checker.yml`. It deletes old workflow runs
   (retaining the latest 2) and optionally prunes old GitHub Releases (keeping 1).

### 2.2 Build Scripts

| Script           | Phase                        | Purpose                                                                 |
|------------------|------------------------------|-------------------------------------------------------------------------|
| `diy-part1.sh`   | Before `feeds update`        | Currently a stub (unused feeds are commented out). Add `src-git` feed overrides here. |
| `cudy-tr3000.sh` | After `feeds install`        | The real customization script. Replaces the upstream `diy-part2.sh`.    |
| `diy-part2.sh`   | Placeholder                  | Template file from the P3TERX upstream; not active in this repo.        |

The key file is **`cudy-tr3000.sh`**. It performs these actions in order:

1. **Theme**: removes `luci-theme-argon` from feeds and clones `jerrykuku/luci-theme-argon` +
   `jerrykuku/luci-app-argon-config` into `package/`.
2. **Golang**: replaces the feeds `golang` package with `sbwml/packages_lang_golang` (branch 26.x).
3. **Passwall packages**: removes several feed networking packages and clones
   `Openwrt-Passwall/openwrt-passwall-packages`.
4. **Passwall2**: removes the feed `luci-app-passwall`, clones `Openwrt-Passwall/openwrt-passwall2`.
5. **Default IP**: patches `package/base-files/files/bin/config_generate` to set `192.168.10.1`.
6. **Image prefix**: patches `include/image.mk` to prepend a date-time stamp (`YYYYMMDD-24.10-6.6-`).

### 2.3 Configuration File

`cudy-tr3000.config` is a full `.config` file generated by `make menuconfig`. Key choices:

- `CONFIG_TARGET_mediatek=y` / `CONFIG_TARGET_mediatek_filogic=y`
- Device: `CONFIG_TARGET_MULTI_PROFILE=y`, includes `cudy_tr3000_v1`
- `CONFIG_PACKAGE_luci-app-passwall2=y` (xray only; no ss/v2ray plugin)
- `CONFIG_PACKAGE_luci-app-argon-config=y`
- `CONFIG_PACKAGE_luci-app-modem=y` + `luci-app-sms-tool=y` + `sms-tool=y` + `sendat=y`
- MTK hardware acceleration: `CONFIG_MTK_HSDMA=y`, `CONFIG_PACKAGE_kmod-mtk_hnat=y`
- USB support: `kmod-usb2`, `kmod-usb3`, `kmod-usb-net`, `kmod-usb-serial-*`
- Kernel modules for 5G modem: RNDIS, USB serial, USB net

### 2.4 Filesystem Overlay

The `files/` directory mirrors the router's root filesystem. Files placed here are copied into the
built image, overwriting defaults from the upstream source.

Currently only `files/etc/opkg/distfeeds.conf` is present, pointing opkg to
`mirrors.vsean.net/openwrt/releases/24.10-SNAPSHOT` for the `core`, `base`, `luci`, `packages`,
`routing`, and `telephony` feeds.

## 3. Key Conventions for Agents

### 3.1 Where to Add New Packages

- **Kernel modules / hardware enablement**: add `CONFIG_PACKAGE_*` entries to `cudy-tr3000.config`.
- **Luci / userland packages that need a makefile copy**: add `git clone` / `svn export` lines to
  `cudy-tr3000.sh`, then add the corresponding `CONFIG_PACKAGE_*` entry to the config.
- **Configuration files shipped in the image**: place them under `files/` mirroring the target path
  (e.g., `files/etc/config/network`).

### 3.2 Image Prefix Convention

The image filename prefix is patched in `cudy-tr3000.sh` via `include/image.mk`:

```
sed -i 's|IMG_PREFIX:=|IMG_PREFIX:=$(shell TZ="Asia/Shanghai" date +"%Y%m%d")-24.10-6.6-|' include/image.mk
```

Any change to the version string (e.g., immmortalwrt version bump) must update this line to match.

### 3.3 Network Defaults

| Parameter     | Value        | Where set                                    |
|---------------|--------------|----------------------------------------------|
| LAN IP        | 192.168.10.1 | `cudy-tr3000.sh` via `config_generate` patch |
| Login password| (none)       | Upstream default                             |
| Wi-Fi SSID    | immortalwrt-2.4G / immortalwrt-5G | Upstream default |

### 3.4 5G Modem Integration

The FM350-GL (Fibocom) modem uses **RNDIS** as the data interface (`/dev/ttyUSB1` AT port,
`eth2` network interface). Key details are documented in `FM350.md`.

Relevant config switches for modem support:

- `kmod-usb-net-rndis`, `kmod-usb-serial-option`, `kmod-usb-serial-wwan`
- `luci-app-modem` + `luci-app-sms-tool` + `sms-tool` + `sendat`
- Do **not** enable `kmod-gobinet`, `kmod-qmi_wwan_*`, or `quectel-CM-5G` — those are for
  Qualcomm-based modems or Quectel modules, not the Intel-based FM350.

### 3.5 Upstream Update Flow

The `update-checker.yml` workflow:

1. Fetches latest commit hash of the upstream repo.
2. Compares against a cached key (`repo-hash_{workflow-filename}_{hash}`).
3. On mismatch: triggers the build and creates a new cache entry.
4. Also checks `defconfig/mt7981-ax3000.config` in the upstream and creates an issue if changed.

When the upstream source is updated, the build automatically picks up the new code — no manual
`.config` update is needed unless new kernel options were added upstream.

## 4. Agent Workflows

### 4.1 Adding a New Luci App

```bash
# 1. Add the clone to cudy-tr3000.sh (after feed installs)
git clone <repo> package/<app-name>

# 2. Add CONFIG_PACKAGE_<app>=y to cudy-tr3000.config

# 3. If the app has luci translations, verify po files or add them
```

### 4.2 Updating the Upstream Version / Branch

1. Update `REPO_BRANCH` in `.github/workflows/openwrt-builder.yml`.
2. Update the `sed` IMG_PREFIX version string in `cudy-tr3000.sh`.
3. Refresh `cudy-tr3000.config` from the new source's `make menuconfig`.
4. Update `files/etc/opkg/distfeeds.conf` feed URLs to match the new release.
5. Update `README.md` version references.

### 4.3 Adding Files to the Image

Place files under `files/` mirroring the target filesystem path:

```
files/etc/config/network   → /etc/config/network (in the firmware)
files/usr/bin/my-script    → /usr/bin/my-script
```

### 4.4 Modifying Build Steps

- Pre-feed-update steps → `diy-part1.sh`
- Post-feed-install steps → `cudy-tr3000.sh` (not `diy-part2.sh`)
- System-level config overrides → `cudy-tr3000.config`

## 5. In-Scope vs. Out-of-Scope

| In scope                                                     | Not in scope                                         |
|--------------------------------------------------------------|-------------------------------------------------------|
| Modifying `cudy-tr3000.sh`, `diy-part1.sh`, `diy-part2.sh`  | Editing the ImmortalWrt source tree (not in repo)     |
| Updating `cudy-tr3000.config`                                | Running `make menuconfig` locally (no source checkout)|
| Adding / updating `files/` overlay                           | Debugging kernel compilation errors in CI runs        |
| Editing GitHub Actions workflows                             | Modifying upstream packages' Makefiles                |
| Updating `README.md`, `cudy-tr3000.md`, `FM350.md`           | Changing CI infrastructure beyond workflow YAML       |
| Modifying `AGENTS.md`                                        | Device tree or kernel config changes                  |
